1. SYSTEM ENTITIES OVERVIEW
--------------------------------------------------------------------------------
The TRDENG persistence layer (MongoDB Atlas / in-memory store) manages 8 core 
entities across the trading lifecycle:

  1. STRATEGIES      : Configuration, hyperparameters, and live state of active algorithms.
  2. ACCOUNTS        : Global account balance, equity, margin, and NAV tracking.
  3. POSITIONS       : Currently active open market contracts per instrument.
  4. TRADES (FILLS)  : Historical execution records of completed or partially filled orders.
  5. SIGNALS         : Raw & blended directional opportunities generated by strategies.
  6. QUOTA_STATE     : Daily trade counters, monthly loss tracking, and circuit breakers.
  7. GATE_REJECTIONS : Audit log of signals rejected by TRDENG's 9-layer risk guard.
  8. DECISION_TRACES : Deep diagnostic telemetry of feature inputs & model weights per decision.

3. DETAILED DATA DICTIONARY & SCHEMAS
--------------------------------------------------------------------------------

3.1 COLLECTION: `strategies`
Purpose: Registry of all plug-and-play strategies (Freqtrade, ORB, VPOC, DRL).
Indexes:
  - { strategy_id: 1 } (Unique)
  - { asset_class: 1, status: 1 }
Fields:
  - _id                 : ObjectId / String (Primary Key, e.g. "strat_crypto_nfi_01")
  - strategy_id         : String (Unique identifier)
  - name                : String (Display name, e.g. "NostalgiaForInfinity Crypto")
  - asset_class         : String ("crypto" | "stock" | "futures")
  - symbols             : Array[String] (e.g. ["BTC-USD", "ETH-USD"])
  - timeframe           : String ("1m", "5m", "15m", "1h", "1d")
  - status              : String ("active", "paused", "backtest_only", "killed")
  - handler_module      : String (Python import path e.g. "strategies.crypto.nfi.NFI")
  - parameters          : Object (Dynamically tuned hyperparameters via Optuna)
                          e.g. { "rsi_len": 14, "atr_mult": 2.2, "bb_std": 2.0 }
  - allocation_weight   : Float (Current capital fraction 0.0 to 1.0 assigned by Meta-Aggregator)
  - performance         : Object { "win_rate": 0.65, "sharpe": 2.1, "total_trades": 142 }
  - updated_at          : Double (UTC epoch timestamp)

3.2 COLLECTION: `positions`
Purpose: Real-time mark-to-market active exposure.
Indexes:
  - { symbol: 1 } (Unique)
  - { status: 1 }
Fields:
  - symbol              : String (Primary Key, e.g. "BTC-USD", "AAPL")
  - trade_id            : String (Foreign key to active trade lifecycle)
  - strategy_id         : String (Foreign key to strategy that initiated position)
  - side                : String ("long" | "short")
  - size                : Float (Absolute volume > 0, up to 6 decimals for crypto)
  - qty                 : Float (Signed volume: positive for long, negative for short)
  - entry_price         : Float (Volume-weighted average entry price)
  - mark_price          : Float (Latest tick / mark price from feed)
  - unrealized_pnl      : Float ((mark_price - entry_price) * size * (1 if long else -1))
  - leverage            : Float (Dynamic leverage factor applied e.g. 3.5x)
  - stop_loss_price     : Float (Active ATR trailing stop level)
  - take_profit_price   : Float (Snapping level e.g. VPOC / VAH / VAL)
  - opened_at           : String (ISO8601 UTC timestamp)
  - updated_at          : Double (UTC epoch timestamp)

3.3 COLLECTION: `trades` (Execution Fills)
Purpose: Historical trade execution audit trail.
Indexes:
  - { trade_id: 1 } (Unique)
  - { strategy_id: 1, closed_at: -1 }
  - { symbol: 1, opened_at: -1 }
Fields:
  - trade_id            : String (UUID, e.g. "trd_8f1a92b4")
  - strategy_id         : String (Foreign key to strategy)
  - symbol              : String (Instrument)
  - side                : String ("long" | "short")
  - size                : Float (Quantity traded)
  - leverage            : Float (Leverage applied)
  - entry_price         : Float (Fill price on entry)
  - exit_price          : Float or Null (Fill price on exit, null while open)
  - realized_pnl        : Float or Null (Booked P&L upon exit)
  - fees_usd            : Float (Exchange transaction fees)
  - slippage_bps        : Float (Execution slippage in basis points)
  - execution_venue     : String ("SIMULATED_OMS", "BINANCE_FUTURES", "ALPACA")
  - status              : String ("open", "closed", "liquidated")
  - opened_at           : String (ISO8601 UTC)
  - closed_at           : String or Null (ISO8601 UTC)

3.4 COLLECTION: `quota`
Purpose: Hard institutional risk gating & monthly loss limits.
Document Key: { "id": "quota_summary" }
Fields:
  - id                  : "quota_summary" (Singleton)
  - crypto              : Object {
                            "trades_today": Int (Limit: 20),
                            "realized_pnl_this_month_usd": Float (Floor: -$1000.0),
                            "last_reset_day": "YYYY-MM-DD",
                            "last_reset_month": "YYYY-MM"
                          }
  - stock               : Object {
                            "trades_today": Int (Limit: 80),
                            "realized_pnl_this_month_usd": Float (Floor: -$1000.0),
                            "last_reset_day": "YYYY-MM-DD",
                            "last_reset_month": "YYYY-MM"
                          }
  - engine_paused       : Boolean (True if -$1000 limit or circuit breaker tripped)
  - pause_reason        : String or Null

3.5 COLLECTION: `gate_rejections`
Purpose: Diagnostic audit of why signals were discarded by the 9-layer gating cadence.
Indexes:
  - { rejected_at: -1 }
  - { gate: 1 }
Fields:
  - rejection_id        : String (UUID)
  - signal_id           : String (Foreign key to signal)
  - strategy_id         : String (Foreign key to strategy)
  - instrument          : String
  - asset_class         : String ("crypto" | "stock")
  - gate                : String ("DEAD_DAY_CHOP", "MONTHLY_LOSS_CAP", "DAILY_CEILING", 
                                  "MICRO_BUFFER_VETO", "LOB_IMBALANCE")
  - reason              : String (Human-readable rationale)
  - rejected_at         : String (ISO8601 UTC)

3.6 COLLECTION: `account`
Purpose: Real-time NAV and purchasing power.
Document Key: { "id": "primary_account" }
Fields:
  - id                  : "primary_account"
  - balance             : Float (Cash balance)
  - equity              : Float (Balance + sum of unrealized_pnl)
  - unrealized_pnl      : Float (Aggregate active position P&L)
  - realized_pnl_today  : Float (Session realized profit/loss)
  - margin_used         : Float (Total collateral pledged)
  - updated_at          : Double (UTC epoch timestamp)


4. DATABASE ACCESS TIERS & FLUSH INTERVALS
--------------------------------------------------------------------------------
TRDENG enforces strict boundaries on database interactions to eliminate latency 
penalties, connection exhaustion, and ballooning I/O costs:

  TIER 1: ZERO LIVE TICKS IN DATABASE (Strict Architectural Invariant)
  --------------------------------------------------------------------
  • Live market ticks (5ms - 20ms) and streaming mark prices NEVER touch MongoDB.
  • All tick processing, CVD accumulation, and VAP histograms are held in RAM
    (`SymbolStateRegistry` thread-safe singleton).
  • Real-time charts stream directly from RAM via the FastAPI WebSocket (`/ws/trading`)
    to the Next.js frontend without database mediation.

  TIER 2: IMMEDIATE TRADE-EVENT PERSISTENCE (Order Fills & Exits)
  --------------------------------------------------------------------
  • Trigger: Strictly on trade lifecycle state transitions:
    - Order Filled (New Position Opened)
    - Position Modified / Partial Exit / ATR Trailing Stop Adjusted
    - Position Closed or Liquidated
  • Collections Updated: `trades`, `positions`, `account`.
  • Latency Budget: Executed asynchronously in a background fire-and-forget worker
    so that trade execution is never blocked by MongoDB network latency.

  TIER 3: PERIODIC INTERVAL BATCH FLUSHES (Non-Frontend Telemetry)
  --------------------------------------------------------------------
  Background telemetry and audit data are buffered in-memory queues and synced to
  MongoDB Atlas at regular intervals via a lightweight background daemon:

  Data Stream           | Flush Interval | Target Collection | Flush Strategy
  ----------------------|----------------|-------------------|------------------
  Quota / Loss Ceiling  | Every 30s      | `quota`           | Single atomic upsert
  Gate Rejection Audits | Every 60s      | `gate_rejections` | Bulk insert (unordered)
  Decision Traces       | Every 60s      | `decision_traces` | Bulk insert (unordered)
  Strategy Performance  | Every 5 mins   | `strategies`      | Upsert Sharpe/WinRate
  Screener Top Rankings | Every 15 mins  | `screener_cache`  | Overwrite latest scan
