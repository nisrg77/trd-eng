1. PIPELINE CADENCE CONTRACT
--------------------------------------------------------------------------------
TRDENG enforces a strict multi-cadence pipeline architecture. Different operations
run at different execution cadences to balance microsecond latency with computational
efficiency:

Cadence Level       | Trigger Frequency     | Operations Executed
--------------------|-----------------------|-------------------------------------------
1. Micro-Tick       | Continuous (Per Tick) | • WebSocket aggTrade ingestion
                    | (~5-20ms)             | • Incremental 500-bin VAP updates (VPOC/VAH/VAL)
                    |                       | • CVD cumulative volume delta divergence
                    |                       | • Order Book Imbalance (OBI) proxy calculation
                    |                       | • Micro-buffer 5ms hold-dwell tracking
--------------------|-----------------------|-------------------------------------------
2. Bar Close        | Per Bar Close         | • OHLCV bar finalization
                    | (1m, 5m, 15m)         | • Fractional Differentiation (FracDiff)
                    |                       | • Technical indicators (pandas-ta / TA-Lib)
                    |                       | • Gaussian HMM Regime Detection
                    |                       | • Strategy Signal Generation (Pure plugins)
                    |                       | • Meta-Aggregator Blending
                    |                       | • Dead-Day Filter (Chop session detector)
--------------------|-----------------------|-------------------------------------------
3. Order Proposal   | Per Signal Trigger    | • Dynamic Leverage Curve (ATR stretch penalty)
                    | (On Demand)           | • Kelly Criterion Risk-Budget USD sizing
                    |                       | • Monthly Loss Ceiling Check (-$1000 limit)
                    |                       | • Daily Trade Counter Check (20 Crypto / 80 Stock)
                    |                       | • Micro-buffer dwell veto
                    |                       | • LOB Imbalance veto (rho > 0.2)
--------------------|-----------------------|-------------------------------------------
4. Execution Fill   | Per Trade Event       | • Realistic Slippage & Fee deduction
                    | (<1ms post-gate)      | • Structural VPOC TP Snapping (TP1/TP2)
                    |                       | • Dynamic ATR Trailing Stop Initialization
                    |                       | • MongoDB Account & Position state sync
                    |                       | • WebSocket Client Broadcast (SCHEMA.md)
--------------------|-----------------------|-------------------------------------------
5. Calendar Session | Periodic (Hourly/Day) | • US Equities RTH Session Gating (09:30-16:00 ET)
                    |                       | • Daily Trade Counter Reset (00:00 UTC)
                    |                       | • Monthly Drawdown Calendar Rollover
                    |                       | • 55 CME SSF Screener Top-Quintile Rescan

4. CONCURRENCY, THREADING & STATE PERSISTENCE
--------------------------------------------------------------------------------

4.1 State Management (`core/symbol_state.py`)
  • Thread-safe singleton (`SymbolStateRegistry`) maintaining historical OHLCV bars,
    active positions, real-time ticks, and incremental VAP bins in RAM.
  • Uses fine-grained reader-writer locks (`threading.RLock`) per symbol to prevent
    race conditions during simultaneous tick ingestion and bar calculations.

4.2 Decision Auditing (`core/decision_trace.py`)
  • Every decision that passes or fails Layer 1 through 9 writes an asynchronous
    diagnostic record to `decision_trace.jsonl` and MongoDB Atlas `gate_rejections`.
  • Non-blocking fire-and-forget logging guarantees that disk I/O never adds latency
    to the active trade execution path.

4.3 Execution Router Bridge (`execution/`)
  • Seamless abstraction between `SimulatedOMS` (paper trading) and `LiveCCXTRouter`
    (production exchange APIs).
  • Both routers enforce 6-decimal micro-crypto precision, ATR trailing stops, and
    immediate emission of `position_update` events matching `SCHEMA.md`.

4.4 Database Interaction Cadence: Zero-Tick Principle & Periodic Interval Flushes
  • Zero Live Ticks in DB: High-frequency market ticks (5ms-20ms) are strictly in-memory
    (`SymbolStateRegistry`) and streamed directly via WebSocket to the frontend.
  • Trade-Driven Immediate Writes: Only fills, position entries, and exits trigger
    asynchronous writes to MongoDB `trades`, `positions`, and `account`.
  • Periodic Background Flushes: Non-frontend operational data is buffered in RAM and
    written at scheduled intervals via a lightweight background task:
      - Quota & circuit breaker status: Flushed every 30 seconds.
      - Gate rejections & decision traces: Batch-inserted every 60 seconds.
      - Strategy performance metrics (Sharpe/Win-rate): Flushed every 5 minutes.
